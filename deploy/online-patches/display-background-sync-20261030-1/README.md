# 展示窗口背景与使用页一致

版本：`display-background-sync-20261030-1`。

## 问题与修改

展示窗口已经通过原有画布快照接收到使用页的账号级配色和光效，但外层 `[data-vivic-stage]` 使用 `bg-black`，深色 React Flow 画布也有自己的纯色底，遮住了唯一的持久共享背景。此外旧展示页仍有全屏黑色加载层。

新增仅作用于 `.vivic-display-root[data-appearance]` 的样式，将舞台和画布底色设为透明，让原有 `AtelierSharedBackground` 正常可见，并隐藏旧黑色加载层。展示窗口初始加载时保留最终背景，继续使用原来的跨窗口画布快照同步账号级主题、四个背景色、光效、速度、强度和动效。

修复实际 `DisplayApp-DkgZz97I.js` 中的背景配置控制器：只有展示端收到可用的完整同步快照后才注册控制器，避免初始化时未加载的默认偏好覆盖缓存的真实背景。等待期间仍使用原来的持久共享背景。

展示页提醒光晕使用正确的初始透明度，避免没有提醒时在挂载首帧先显示琥珀色光晕再淡出；正常提醒的后续渐变仍保留。

不新增背景副本或偏好存储，不改 React 根、实际启动入口、运行模块、后端、用户数据库或模型服务。保留上一版本的背景菜单字体修复和其他已上线功能。

## 验证

候选与线上分别保存 `candidate-verification.json`、`live-verification.json`。使用真正的「展示窗口」按钮打开弹窗，验证预设、自选四色、深浅色、五种光效、速度/强度、三种动效、深色工作画布、展示页刷新、使用页刷新、带登录历史重开、切换存档后的固定展示窗口和手机宽度。

使用隔离模拟账号接口，所有画布与偏好数据仅留在测试进程。线上验收使用公开域名真实 HTML/JS/CSS，不替换静态资源。未创建生产测试账号。

`*-pixel-verification.json` 比较两窗口实际截图的背景区域像素，并对延迟 1800ms 会话请求时的真实录屏逐帧采样，检查首次背景绘制后没有黑屏或背景切换闪烁。录屏与截图保存在工作区 `display-background-sync/`。
