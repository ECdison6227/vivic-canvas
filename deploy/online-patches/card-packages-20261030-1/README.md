# 服务器卡片包管理与 v0.2 运行时

用户在原对话明确授权接手运行时、服务器包管理、定义刷新，并要求截图；这是原 F5 对接单的实施，不重新开启产品设计。

入口：当前线上设置 → 数据 → 卡片包。沿用 Hark 设置布局；先校验并看 DEMO，再确认安装。提供版本详情、启停、下载、卸载确认及引用保护反馈；真实卡片只能由用户指令生成，DEMO 不写入 Space。

当前线上只有打包产物与补丁，仓库旧页面不代表线上。`scripts/build-card-package-patch.mjs` 在完整校验的旧发布副本上创建新资源目录，只新增管理组件、共享运行时和刷新监听，保留同事所有其他文件。不会用旧源码全量构建覆盖线上。

同一 `packages/card-runtime/src` 编译出的运行时负责文件预览、安装列表重验、下载重验、现有显示页与规划预检。启停与安装通过正常同源 Cookie API；定义变更使用无数据的事件与 BroadcastChannel 通知，每个标签页独立读取当前账号定义。无 IndexedDB 回退。

构建：`node scripts/build-card-package-patch.mjs <现有发布副本> <不存在的目标目录>`。线上切换前必须核对基础发布逐文件哈希、检查磁盘和健康状态，保留原指针供回滚。F5仍须用户亲自导入并说一句话建卡，之后才进入G。
