# 2026-10-23 三线集成

用户明确授权三个 subagent 开始：手机接新线上会话、服务器环境验证、跨平台启动器及本地模型。此指令恢复本地运行工作；仍沿用此前“不正式发布”的约束，保留全部未提交成果，不推送 GitHub。

## 边界与验收

1. **手机线上接入**：电脑浏览器先配置并创建 owner；二维码仅绑定对应在线会话。手机只有聊天与纵向 Space，不建立 owner/画布DB，不取得模型 Key。采用同源 HTTPS 长轮询和已有严格 Frame / 白名单 projection / 受控 Action / 保存回执；撤权和会话过期终止权限。网页入口 `/remote/` 不触发桌面会话 bootstrap；Android 保留可信来源确认。主 agent 负责 App/ControlApp/设置折叠入口，手机 agent 负责协议、会话后端和 APK。
2. **服务器验收**：只使用全新隔离 staging、现有 Docker 和回环端口，验证 Linux 原生依赖、真实服务入口、HTTPS 证书校验、反代、隔离会话和流式/手机请求。现有公开站、中继和旅游服务不替换，不安装系统 daemon，不开放新公网端口。记录资源边界和自身 staging 清理方法，不做全局清理。
3. **本地运行**：保留 Qwen 已验证路径，新增真实 StartLux 官方兼容服务的一键准备/运行/停止及可替换权重机制；开发训练与留出评测流水线，结果与训练硬件条件分别记录。动态 TTS 复用 Sherpa-ONNX，只生成并检查音频文件，不播放。Mac 必须实际 Mac 运行才能标为验收，缺机器时交付可复现的安装和自动验收流程。

所有 UI 继续使用 `rea-ui-library@26ac2724/platforms/web/hark` 的现有组件、原字体、SVG、连续圆角和透明材质；主界面保持简洁，不恢复 TODAY UI、手机五标签或旧全屏设置。公共依赖、App/ControlApp、音频/provider 集成由主 agent 统一处理。各线使用独立端口和自造数据，浏览器/Android 运行须协调单一控制者。

真实模型推理、真实训练、离线音频合成、文件级安装验证、Mac 实机和 Docker/TLS 验收分别报告；任何模拟响应均明确说明，不替代真实运行结论。
