## 浏览器失败排查与待复核

路由改为懒加载后，`page.goto()` 返回不再代表 Display 的调试接口及异步同步客户端已就绪。E2E 的公共 Display helper 现在等待运行时状态；有指定画布时还等待该画布完成 hydration。直接打开 Display 的卡片用例也等待运行时；刷新后的布局轮询允许接口暂时不存在，然后等待真实保存布局出现。几何断言没有放宽。

旧的 auto-fit 用例通过用户输入连续创建三个计时器，却期待全部卡片自动适配屏幕。现有 `focusResponseActions` 会为每次直接响应追加聚焦，自动适配逻辑则明确让聚焦优先。第三张计时器位于 x=624、宽 264，在 800 像素窗口以 zoom=1 居中后，视口 x 恰为 `400 - (624 + 132) = -356`，与失败值一致。该聚焦策略存在于本轮改动之前，失败不是拖动优化改变了几何。

该用例已改为通过 owner 直接创建三张计时器，明确不带聚焦，等待 Display 测量尺寸后覆盖自动溢出适配路径；保留原来的全部边界和缩放断言，并增加当前无聚焦断言。直接响应的聚焦策略仍由既有单元测试覆盖。此处未修改产品的相机或布局逻辑。

上述浏览器 helper 与 auto-fit 修订已通过定向 lint；本文写入时，稳定源码上的浏览器复测尚待集成负责人汇总，不能记作全部通过。测试使用独立浏览器 context、隔离端口 5174/8788，并串行占用浏览器测试时段。
