# Windows 启动器补充验收

2026-10-22，Windows x64。基于已通过验收的固定 llama.cpp/Qwen 运行包继续修复；未更换运行引擎、模型或评分门槛。测试静音、不采集物理麦克风，浏览器使用独立 context。

## 修复与入口

- `Start-Vivic` 核对可执行文件、完整入口和进程创建时间后，仍等待 `/healthz` 成功才打开 `/launcher`。同一包的并发启动/停止使用命名互斥锁。失败启动回收本次新建进程及状态；占用端口不会被自动停止。
- 启动支持 `-Port`，状态文件保存实际端口。`Stop-Vivic` 校验进程身份，并等待所属 guardian 完成模型退出。
- 安装支持 `-Destination`、`-NoShortcuts`；拒绝覆盖既有目录，拒绝安装到源目录内部。默认安装保留既有桌面快捷方式，为新版本创建带时间戳的入口。复制时排除本地会话配置、日志和运行状态。
- 模型取消后等待正在结束的文件工作再接受重试；停止首先显示 `stopping`，确认文件操作和所属引擎已结束后才显示 `cached`。错误启动的回收也保留这一状态。
- 独立 `/launcher` 提供打开画布、展示页、设置、准备/启动/停止和清理模型。它不创建 owner，不打开画布 IndexedDB。状态轮询失败时撤销上次“就绪”，重连恢复；过期轮询不能覆盖后续停止结果；重复点击不会重复请求。受控外部 provider 不显示本地下载，也不把启用当作已验证健康。

- 启动器 5 项测试通过：断连/重连、陈旧轮询、重复启动、下载/降级反馈与 provider 模式。启动器局部 lint 通过，Web/API 类型检查通过，Web production build 通过。
- 从已部署的普通文件包复制依赖、更新源码与 Web production build，再运行新版安装器到 `.cache/windows-launcher-audit-20261022/relocated 安装`，使用独立 18788 端口和复制出的独立模型缓存。
- 实际浏览器完成本地模型启动/预热/停止；清理对话框取消保留缓存；运行 Stop 后页面改报断连；重新 Start 后不用刷新页面即可恢复；再次 Start 复用同一已验证 PID。0 JavaScript 错误，0 画布 IndexedDB 打开，没有麦克风调用。
- 实际故障注入确认：伪造旧创建时间不会停止同 PID 的活进程；占用端口拒绝启动且保留已有服务；入口抛出启动错误后没有残留监听或状态文件；恢复入口后可再次启动和停止。

## 体验与边界

双击新包 `Start-Vivic.cmd` → 浏览器本机工作台 → 准备模型 → 启动模型 → 等待“模型已就绪” → 打开画布。文字生成仍使用设置中连接的主模型。结束体验运行该包的 `Stop-Vivic.cmd`；只关闭浏览器会保留后台服务。

当前仍是 Windows x64 CPU 固定运行包；没有自动下载 Ollama 或更大的模型，没有新增权重训练或放宽接受阈值。真实网络大文件下载/取消沿用前轮验收，本次重新校验并离线复用固定缓存。没有覆盖全部安全软件、Windows 版本或 GPU 环境。
