# Android 全量验收与电脑安装包入口 · 2026-10-24

本轮已在独立 Android AVD 中实际完成扫码配对、同步已有 Space 内容与进度、手机指令保存、重连和撤权。扫码经过 APK 原生相机 Activity 与 ZXing 解码，没有用粘贴链接替代。初始四张卡使用标注 TEST 的生成响应 fixture；后续手机建便笺走真实线上 API、电脑 owner 和持久化链路。本报告不作为 StepFun 或本地模型质量测试结论。

**安装包区分：最终生产 0.1.6 APK 验证了下载、签名、安装和启动；完整扫码/远控链路随后换装同源码同版本的 `0.1.6-debug.apk` 执行。测试 CA 只嵌入 debug APK，并由该应用的 `networkSecurityConfig` → `debug-overrides` → `trust-anchors` 加载；没有安装到模拟器 OS 或 Windows 系统信任库。手机 `https://localhost:19445` 经 `adb reverse` 到 Windows 私有 TLS 代理及 18995 API，电脑 Chrome 测试 context 单独忽略测试证书错误。这不是生产 APK 经正式外部 HTTPS 域名/跨公网的端到端验收。**

## 本轮改动

- 电脑设置的手机连接区域新增一个复用现有 Hark 按钮样式的“下载安卓 App”入口。本地与线上共用 `/downloads/Vivic-Remote.apk`；只有存在合法下载清单才显示，源码开发环境不会出现无效下载按钮。
- `scripts/stage-android-download.mjs` 在 Windows、Mac、线上打包前暂存生产 APK。核对 Manifest 版本、构建回执、SHA256、必需文件和禁止的调试/测试 CA 内容；缺包或调试包明确失败。二进制和清单位于忽略的 `apps/web/public/downloads/`，不提交到源码。
- macOS 手动 CI 增加 Windows Android 构建任务，产出相同源码的非调试 APK，再交给 Mac 双架构打包任务。没有触发 CI、上传 GitHub 或公开发布。临时 CI 开发签名不是稳定发布签名，不能覆盖以其他签名安装的 App。
- 新增隔离原生完整 Playwright 配置/场景，补齐真实扫码证据。既有原生权限脚本增加 AVD 身份检查与调试请求超时；保留拒绝、取消、释放相机、阻止外链和空存储断言。
- 手机浏览器测试明确要求 `127.0.0.1`，并用独立 `5184` 端口；原配置允许 `127.0.0.2`，但产品本机开发中继输入只在 `127.0.0.1/localhost` 开启，现改为启动前明确报错。

本轮没有改手机执行权限、原生扫码业务逻辑或恢复复杂手机设置。

原生组合场景检查：

1. 在电脑实际点击下载 APK，保存的文件大小/SHA256 与生产清单一致。
2. 将下载所得生产 APK 安装进 AVD，实际启动，确认包不是 DEBUGGABLE。
3. 换用同版本、仅加入精确私有测试 CA 的 debug 包进行本机 HTTPS 验收；原生 ZXing 从虚拟相机帧读出电脑真实二维码，显示主机确认，配对后关闭相机并消耗一次性码。
4. 使用真实 Android 横滑进入 Space，立即看到电脑已有便笺正文、待办完成态、目标 `3 / 10` 和持续变化的倒计时。
5. 电脑通过传送门把待办移到用户页编辑、再放回展示；手机内容随之更新。手机固定卡片和文字新建便笺在真实 owner 保存后报告成功，Display 显示同一结果。
6. 根据原生 WebView 边界及实际输入框 DOM 位置点击，真实 Android 输入法弹出并压缩视口；输入框留在键盘上方，返回键关闭键盘。
7. 手机设置只有外观、文字和连接；深色、较大文字、原生返回与窄屏布局正常。
8. 手机主动断开时写操作禁用；同一进程中的重新连接恢复已有授权。
9. 后台返回保留连接；电脑撤权立即禁用手机。电脑刷新后已创建卡片和待办编辑仍在。
10. 另行撤销相机权限，通过系统拒绝按钮验证手动配对回退；再次授权后验证取消扫码、相机释放、关闭设置、阻止外部主页面导航与浏览器存储为空。

## 实际边界

- 手机是已配对电脑的遥控。电脑聊天页仍需打开并拥有画布 owner；未增加脱离电脑运行的后台 owner。
- 初次配置留在电脑；手机仅聊天和单列 Space。卡片通过现有白名单内容投影同步，不复制桌面自由画布，也不授予任意扩展执行权限。
- 同进程后台恢复与主动断开/重连已验。刷新手机页面或杀掉 App 进程仍会丢弃内存凭据，需要重新扫码；这是现有授权生命周期，不能称作持久自动登录。
- 本机 HTTPS 用精确测试 CA 的专用 debug 包；交付生产 APK 不含该 CA/调试能力。真实公网正式域名下的生产 APK HTTPS 接入仍随发布环境验收。
- Mac 实机和 StepFun/本地模型由另外两条验收线负责，本报告不把模拟器结果当作实体手机或模型验证。

测试使用 18995/19445、原生调试转发 9338、专用 `emulator-5610`；退出关闭任务服务、转发和 AVD。手机浏览器用 127.0.0.1:5184，结束后关闭，未更改用户原有服务或画布。
