## 实际交付

PLAT-01 使用严格 ProviderResult/TravelOffersCard、字段策略、query-only 场景、确定性 builder 和可替换适配器。默认旅游适配器不联网，显示 DEMO；用户备注/选择可编辑，服务结果与查询不能由普通 update 或删除重建同 ID 绕过。刷新检查当前 owner、画布、请求代次及查询状态，保留刷新期间的最新备注。

PLAT-02 支持 `.vivicard` 声明式包、受限 JSON Schema、JSON Pointer、九类受控组件、ZIP/CRC/路径/解压限制和 SHA-256。Test Space 使用独立内存 reducer，无真实画布、模型或网络副作用；参数草稿非法时不能试跑/安装。安装和重启重验内容；禁用/卸载保留实例，重装原包恢复。迟到加载不能覆盖安装/禁用/卸载，清除数据不能被取消重装恢复旧定义。

开发者可用 `pnpm card:check`、`pnpm card:pack` 检查和制作跨平台包。参考 `examples/card-packages/goal-progress/`，实际 ZIP 交付于外层 `delivery/card-platform/goal-progress.vivicard`，内容 hash `2a3063f8a73a5f05b92b46be20703281f1b0a40010d8452ea0c43f2dc9626057`。

底层改动包括有限上下文及摘要保护、DB v2/逐卡恢复与原文备份、超过 200 卡的导入恢复、路由/重组件拆包、稳定渲染引用、Windows 启动清理、lint/CI 冒烟与并行测试。请求阶段使用 SSE 和 requestId；日志只有阶段/时长/路由等元数据。决策故障冷却 30 秒，手动重新启用可立即尝试。语音配置变更只取消语音，不再误取消独立文字规划。
