# 卡片传送门与可见画布操作验收

2026-10-22，用户反馈两个标签页之间不方便拖拽，且缺少聚焦、显示全部等可见入口。本轮在 `feat/card-platform-runtime` 实现并本地验收，未推送或发布。

## 行为

- 用户页顶部、展示页左下均提供“卡片传送门”：点开后可以搜索当前画布卡片、一键双向传送，或把本页卡片拖进传送区。传送不创建副本。
- 用户页接收后可以编辑旅游选择、备注和刷新结果；卡片上有文字按钮“传送到展示页”。展开传送门也可从任一端收回/送出卡片。
- 展示卡片悬停或键盘聚焦时显示“聚焦”“传送”；用户页顶部和展示页右下提供“显示全部”，聚焦后可“恢复视图”。显示全部只适配视图，不改变固定卡片坐标。
- 恢复使用该展示窗口聚焦前的真实相机位置/缩放，不使用 owner 的另一份视口；显示全部不会与恢复动画竞争。关闭 React Flow 对子控件键盘聚焦的自动平移，保留显式聚焦操作。
- 所有 Display 操作均通过窄请求交给 owner。校验画布、owner epoch、版本、布局基线、来源表面及有效目标，持久化后发布确认；无主控时禁用操作。展示端不持有任意 ActionEnvelope 或写数据库的能力。
- 固定到非活动画布的展示页不切换主控当前画布。视图状态只在当前 owner 会话中保留。连接通知使用现有同步事件和过期计时器，无新增轮询。

## 实际验证

- 前端全量单元测试 **595/595** 通过；其中同步测试 **78/78**。最后相机/主题回归 **11/11** 通过，保留原共享主题时钟断言。
- Web typecheck、全仓 lint 和生产构建通过；lint 保留既有 72 条 warning，构建仍有既有大 chunk/WASM/Vite 提示，没有降低规则或屏蔽失败。
- 新增 `card-portal.spec.ts` 最终 **3/3** 通过：旅游 DEMO 跨标签页传送、选择/备注/刷新/返回/重载；聚焦、原视图恢复、全部显示、固定位置和 owner 断开；同标签页真实拖入传送区及点击返回，同时检查深色和 390px 窄屏布局。
- 原 `canvas-interaction.spec.ts` **2/2** 分批通过：拖动持久化、固定/撤销，以及 60 卡片在 800×600 展示页适配。不声称运行了整个浏览器套件。
- 复验中曾出现开发中 HMR 引用尚未落盘的新接口，以及恢复视口时 React Flow 子控件自动平移的冲突。接口补齐、相机恢复和自动平移修正后重新执行。截图发现回传按钮文字受图标按钮固定宽度限制，已改成自适应宽度并重新通过三项浏览器流程。
- 截图保存在忽略目录 `evidence/card-portal-20261022/`，已检查浅色旅游编辑页、展示页控件、深色传送门及窄屏布局。测试使用独立浏览器上下文、5174/8788 和静音配置；没有更改用户画布或调用真实模型。

## 体验

当前预览前端 `http://127.0.0.1:5176/`，API 8789，原 5175/8787 保留。刷新用户页与展示页后生效。输入“下周去杭州住两晚，预算500”，从传送门送到用户页编辑再传回。旅游数据仍为 DEMO；真实飞猪、模型质量验证边界没有变化。
