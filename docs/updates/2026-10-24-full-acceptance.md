## 修复与改动

- 电脑手机连接面板加入“下载安卓 App”。Windows、Mac、线上包均携带经SHA256和生产构建检查的APK；仍使用原0.1.6包，手机产品代码未变。
- 修复Space子卡片编辑弹层被面板遮挡、无法点击保存。
- 恢复backend-first任务接线后遗漏的严格离线命令：唯一目标聚焦/删除/高亮、便笺展开折叠、普通提醒暂停继续、指定待办完成/高亮。仍经过版本、owner和保存回执；不能用规则绕过已拒绝的模型结果。
- 修复通知正文被模型仅口头确认、不建通知卡；修复“用柱状图记录”的格式支持。
- 网页过大时准确报告读取上限，避免销毁连接产生的事件误报“连接中断”；未放宽256KiB限制。
- 修复Mac语音依赖锁遗漏`sherpa-onnx-core`，保持版本和hash校验；修复安装复制将相对依赖链接指向原解压目录的问题。
- 补齐正常后台节流、冻结恢复、真实备份导入导出、扫码、输入法和安装后的运行验收。
- 既有公网中继使用原授权测试端口补验：二维码配对、手机正文、固定、保存重载、切画布及撤权均通过。没有新增公网部署或修改服务器白名单；这不代替新线上体系的生产APK正式域名验收。

## 安装与体验

线上版使用StepFun API Key即可进入聊天和Space。本轮验证的是用户提供的 **Coding Plan Key / Plan端点**，未暗中切换按量计费接口。

本地Windows为ZIP安装器：解压后运行`Install-Vivic.cmd`，然后运行安装目录里的`Start-Vivic.cmd`。Mac为arm64预览ZIP：解压后运行`Install-Vivic.command`生成`.app`。本地运行不预装模型权重，按需准备；关闭浏览器不会停止本地服务，结束时使用`Stop-Vivic`。

电脑完成首次配置后，在设置→连接→手机连接下载APK并生成二维码。手机确认电脑后可聊天、横滑到单列Space；同步已有正文、待办完成状态、目标进度、倒计时和后续编辑。电脑聊天页需保持打开并拥有当前画布。手机进程被杀或页面完全刷新后需重新扫码，不宣称永久登录或脱离电脑运行。

## Browser Extension

本轮**不增加扩展**。正常后台节流、展示窗口打开、冻结后恢复补齐、owner接管、持久化及重载均已通过。没有证据表明当前稳定性需要额外安装扩展。扩展自身也有可停止的生命周期；未来若需要跨站采集或右键收藏，再按具体能力设计。[Chrome官方生命周期说明](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)

## 仍需区分的边界

1. **正式Jev尚未达标。** 4B能运行，但5条完整v2任务虽都返回有效概率，0/5通过执行门控，约14秒/条。需要特调权重、校准和性能优化；默认门控保持关闭。基础模型运行成功不等于已完成Jev训练。
2. **原生扫码使用专用测试包验本机HTTPS。** 生产0.1.6完成下载、验签、安装和启动；完整扫码远控使用同源码同版本、仅在包内信任精确私有CA的debug变体。生产APK经正式公网HTTPS的全链验收留到发布环境，本轮没有公开发布。
3. **Mac包未签名/未公证。** 已验实际`.app`执行和Chrome访问Mac服务；未验Finder首次Gatekeeper批准、Safari或Intel Mac。未绕过安全提示。
4. **Windows资源限制。** 4B缓存准备通过，但当前Windows可用内存不足，未强行加载。最终依赖锁复验时0.8B缓存准备也通过，随后因可用内存约0.7GiB被验收脚本拒绝再次加载；本轮此前的0.8B/TTS成功记录保留，不能把这次未运行重试记为成功。
5. 自动化不采集物理麦克风/相机，不播放声音；唤醒准确率与主观音色仍需本人设备体验。旅行仍是明确标注的DEMO，未接真实飞猪交易/MCP。
