# Mac 单屏 + 安卓手机测试

适用版本：PR #19 合入后的 `main`，Android 0.1.9 / code 10。不要使用早期 0.1.6 手机包或旧 Mac ZIP 来验收本轮文件与传送门。

**主流程已经实现，但项目还不是“全部完成、只剩测试”。** 正式线上部署、外部账号授权、原生决策模型质量、商店级签名与真实语音体验仍各有未完成项。下面把可用流程、运行条件和验收边界分开。

## 1. 先启动 Mac

### 已有新版 Mac 安装包

Apple Silicon（M1/M2/M3/M4 等）用 `arm64`，Intel 用 `x64`。解压对应 ZIP，运行 `Install-Vivic.command` 安装，再打开生成的 Vivic.app。也可以运行解压目录的 `Start-Vivic.command`。

安装器内置对应架构的 Node，无需另装全局 Node 或模型。首次出现 macOS 安全提示时，通过系统正常的“打开”授权；本包未签名公证，不关闭系统安全检查。若安装路径已存在，选择新的安装路径，先不要覆盖旧版本。

启动后先点“打开 Vivic”，在设置→连接中填入 **StepFun Coding Plan** Key；本项目目前测试的是 Plan 端点，不将普通按量 Key 或免费 Key 的可用性视为已通过。第一次只测 API，不下载本地模型。

### 由 Mac 上的 Agent 从源码启动

使用 Node 24.21.0、pnpm 12.11.2；以下是终端命令，不包含任何 Key：

```sh
git clone https://github.com/ECdison6227/vivic-canvas.git
cd vivic-canvas
pnpm install --frozen-lockfile
pnpm dev
```

已有克隆时先检查未提交改动，再切换 `main` 并 `git pull --ff-only`，不要用 reset 覆盖本机工作。按终端输出打开本地地址（默认 Web 从 5173 开始选可用端口、API 8787）；持续使用同一个浏览器、profile 和地址，避免把不同 origin 的存储误认为丢失。

这是本地开发模式，连接页不等于线上的三步新手引导。要单独测线上引导，按 [线上部署文档](../online-deployment.md) 的本机预览命令运行；本机 `localhost` 的线上预览地址不能直接让实体手机访问。

## 2. 单屏怎么用

1. Mac 保留最初的聊天/控制标签页，它负责执行、保存和手机会话。
2. 点顶部“展示窗口”，打开同一 Space 的展示页；把这个窗口放在 Mac 屏幕前台。
3. 安卓扫码后以手机聊天页发送指令，Mac 展示卡片；手机横滑到纵向 Space 查看同一批内容。

**保持 Mac 清醒、浏览器运行、原控制页不关闭。** 控制页可以放在后台。Mac 睡眠/关机时手机不能继续执行；手机杀进程后要重新扫码。一个屏幕足够，不需要浏览器扩展。

## 3. 手机连接前必须具备的条件

- 安卓安装匹配版本 APK。电脑包携带 APK 时，设置→连接→手机连接中可下载；源码克隆不会自动带安装包。
- **本地 Mac 模式**需要私有 `~/.vivic/mobile-relay.json` 和可用的 HTTPS/WSS 中继。源码/安装包不会携带这个秘密配置。让本地 Agent 通过可信通道配置，文件权限设为 `600`；不要把其中的 `admissionSecret` 发到聊天、截图或 GitHub。
- 配置包含 `relayUrl`、`mobileUrl`、`admissionSecret`、`origin`。`origin` 和电脑网页的实际 origin 都要被中继允许，安卓来源为 `https://appassets.androidplatform.net`。保留后端的 loopback 限制，不为扫码把本地带凭据 API 暴露到公网。
- **线上模式**需要手机可达、证书受信任的正式 HTTPS 入口，并运行本次配套后端；扫描包含 `online=1` 的完整链接。手机的 `localhost` 指向手机自己，不是 Mac。
- 文件下载和新传送门还要求中继/后端支持本次 `file.read` / `card.surface` 权限。旧中继能聊天并不证明这两项已升级；此前公开中继没有在本轮自动更新。

满足条件后：电脑设置→连接→手机连接→生成连接二维码；手机“扫描电脑二维码”，正常授权相机并确认电脑。一次性码过期就重新生成，模型 Key 只在电脑配置。没有上述私有配置时，“中继暂不可用”表示环境未配置，不应跳过后继续写“手机全通过”。

## 4. 推荐测试顺序（约 30–45 分钟，不含模型下载）

| 测试 | 操作 | 应看到的结果 |
| --- | --- | --- |
| API 与设置 | 验证 Key；切到偏好/数据再回来；输入未发送文字后开关设置 | 连接明确成功；草稿保留；设置仍是三个小分组 |
| 基础指令 | 手机发送“加待办：核对车票”“十分钟倒计时”；再自然语言生成一份三日旅行准备清单 | 手机收到执行结果，Mac Space 出现对应卡片；行程若为演示应标注 DEMO，不伪造订单或票价 |
| 实时同步 | Mac 修改待办或进度；手机查看；然后手机发一条修改指令 | 两边内容一致，成功后刷新电脑仍存在，不重复建卡 |
| 真正传送门 | 手机 Space 上点一张卡的“移到聊天” | 从手机 Space 和电脑展示页消失，只在用户/聊天侧显示；移回 Space 后反向恢复；正文与子卡保留 |
| 卡片操作 | Mac 传送门聚焦/显示全部/恢复；拖动、固定；排序分区预览再应用 | 聚焦/恢复正确；固定卡不被整理挪走；应用前可预览 |
| 撤销重做 | 删除一张测试卡、撤销、重做，再撤销；整理后撤销 | 卡片和内容正确恢复，只影响当前空间 |
| PDF / MD | 上传一份多页 PDF、一份带标题/列表的 MD；整卡点开；PDF 翻页；手机阅读与下载 | 打开即读；问 Vivic 需主动展开；下载原件保持不变；Word/TXT/CSV/JSON 新上传被拒绝 |
| 文件限额 | 先试 5 个小文件；再试 6 个，或合计超过 10 MB | 合规成功；超限整批拒绝，无半批文件卡；空间容量明确不超过 100 MB |
| 连续性 | 刷新展示页；手机断网后重连；手机锁屏再回；最后电脑撤销手机授权 | 显示当前已保存内容；断线不虚报成功；不确定结果先核对；撤权后手机不能继续操作 |
| 空间与备份 | 新建第二个 Space，来回切换；导出/导入测试画布 | 内容隔离；手机跟随当前空间。JSON 备份只含卡片结构，不包含文件原件 |
| Hark 与动效 | 深/浅色、空间光效关闭/弱/强、减少动态；手机较大字号与软键盘 | 文字清楚、无横向溢出/键盘遮挡；关闭动态后稳定；不恢复一排常驻参数 |
| 外部查询（授权后） | 在电脑连接飞书等服务，通过“＋→查询资料”查找并保存结果 | 来源、时间、失败信息清楚；结果可读；没有授权时不能冒充已查到数据 |

所有破坏性操作仅用新建的测试 Space；100 MB 容量可由自动化覆盖，不必为了手测填满私人空间。

## 5. 本地模型和语音单独测试

API 主流程通过后再进入 `/launcher`，查看推荐配置和下载大小。先用 0.8B 验准备→启动→运行→停止；资源足够再测 4B。停止后应释放进程，再次启动复用已验证缓存。普通电脑不能因为测试强制使用 4B，也不自动下载所有模型。

本地小模型负责受限决策，不等于完整通用 LLM。复杂内容生成、联网和某些语音配置仍可能使用在线服务。“本地模型启动成功”不能写作“整个助手完全离线可用”。正式特调 Jev v2 质量门控仍未通过，保持关闭。

手动测试按住说话、取消录音、识别后检查/发送、识别期间改草稿；唤醒默认关闭，用户开启后再试呼叫、安静环境误唤醒和停止。手机 App 目前以文字遥控为主，不应期待它包含电脑上的全部模型/语音功能。TTS 主观音色、唤醒准确率和物理麦克风需要本人实际体验，先前静音自动化不能代替这一步。
