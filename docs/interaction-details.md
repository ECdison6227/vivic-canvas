# 子卡片、逐项定位与编号选择

2026-10-16，按用户反馈在 `agent/next-iteration` 实施。本文记录当时的子卡片交付；后续排版/长文/快速找卡也已完成，见 [体验交付](archive/2026-10/experience-20261016.md)。当前验收入口为 [完整清单](FINAL_ACCEPTANCE_CHECKLIST.md)。

## 使用入口

1. 打开 `http://localhost:5173/control`，在「卡片与子卡片」打开一张卡片。
2. 「整张卡片的扩充」或待办/表格/便笺行旁的扩充按钮打开小窗。输入补充内容，点击「保存子卡片」。同一目标可添加多张，也可编辑和删除。
3. Display 只为已有子卡片显示入口，打开后箭头指向原行；Escape 或关闭按钮收起，并恢复焦点。内容可滚动、选择和复制。
4. 合并提醒仍由每项独立 ID 组成。试「高亮喝水提醒」「删除喝水提醒」「删除第二个提醒」，只操作其中一项；「撤销」恢复已删除提醒。
5. 多候选时，卡片左上角或合并提醒行旁显示号码，Control 同样列出编号与事项摘要。回复「2号」「第二个」或点击候选确认；悬停或键盘聚焦候选先预览高亮。输入「取消」或在输入框按 Escape 结束选择。

## 数据与生命周期

- 子卡片保存在父卡片 `metadata.subcards`，通过严格校验的 `card.subcard.set/delete` Action 修改；不会另造一份父内容或改变 Note.variant、画布布局、密度、固定状态。父卡片导入/导出、同步及删除撤销自然携带扩充内容。
- 每张父卡片最多 24 张子卡片，每张最多 2,000 字。Markdown 使用已有 renderer，没有增加依赖。模型规划器不自行创建或删改子卡片。
- 待办以稳定 item ID 关联，重排和修改文字不串行。表格/便笺原来没有行 ID，因此绑定原行位置及内容签名；改写/重排后失效的子卡片留在 Control 的「原行已改变」区域，可显式移到整卡。不会静默丢弃内容或自动关联相似行。
- 临时选择保存冻结的 ID 列表，后续新卡不插入当前编号。两分钟过期；任一候选消失、到时退出、切画布、失去控制权或新的指令都会取消本次选择。编号不写进持久化画布，也不受 12 条模型 Action 上限影响。
- Display 阅读小窗跟随当前父卡和原行；删除、关联变化、切画布或 owner 变化时关闭。没有额外 React Flow 节点、自动挤位、额外模糊层或每卡常驻动画。仅打开的 Popover 跟随平移/缩放重新定位；淡入遵循减少动效。
- 另外修正固定 React Flow 节点的阅读点击穿透、Portal 深浅色 tokens、窄屏避让，以及切画布后立即编辑时保存队列变化导致切换 snapshot 丢失的问题。便笺分行渲染保留原始换行，复制/旧展开收起检查不丢原文。

## 适用边界

- 这轮是手动编辑的一级文字子卡片，不是无限层级思维导图，也不会自动调用 GPT 扩写或虚构数据。搜索/天气/图表可对整张卡片补充；待办/表格/便笺支持具体原行。
- 子卡片补充说明与已完成的 Control 长文详情是不同入口；完整文章/长便笺阅读、全拼/首字母找卡、排版材质见 [体验交付](archive/2026-10/experience-20261016.md)，无需重新开发。
- Display 仍沿用原卡可见行数；隐藏待办项的扩充可先从 Control 阅读。子卡片自身的删除不进入父卡片删除撤销栈，父卡片删除撤销仍整体恢复。
- 自动化使用隔离 TEST 画布和 5174/8788，保持静音、不采集麦克风。未操作用户真实画布；真实语音与物理设备体验仍由用户后续验收。
