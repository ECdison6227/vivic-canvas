# 二期优化：一次完成一条日常使用流程

更新：2026-10-16。用户要求总结并拓展后续优化。**本文件是讨论方案，尚未启动二期实现；新增卡片选型、部署架构与各阶段顺序仍有待确认。** 现有修复及验证见 [使用反馈报告](user-feedback-20261016.md)；不再要求用户先机械重做整套输入清单。

二期主线：自然表达能持续协同，第一次打开就容易上手，再把同一套体验扩到内测用户和手机。用户已明确希望逐个推进，避免功能和设置堆积。

## 已确定的方向与现有基础

- Control 负责输入、连接、设置和管理；Display 继续只保留必要内容与短暂反馈。
- 新卡片复用真实 Assistant UI styled registry 和已批准组件，一次完成一种的完整使用流程。
- 每个用户连接自己的 Pi/OAuth 账号、使用自己的模型能力与额度；StepFun Coding Plan 保留个人配置路径。
- 考虑内测码、邮箱候补邀请，以及手机网页的语音、设置和照片输入；这些后于当前体验优化。
- 固定 Orb、普通/计划提醒分组、到时退场、独立提示音、天气/搜索、长文详情、子卡片和中文/拼音找卡已经实现，继续改进使用衔接。
- 真实听感、物理麦克风、输入法、Safari 和外接屏仍有现场验收项；安排在对应体验优化时补齐，不用重复开发现有模块。

## 建议推进顺序

| 阶段 | 交付重点 | 通过标准 |
| --- | --- | --- |
| A | 自然表达与连续协同 | 连续补充、修改、指代同一张卡片；能直接回答或查询，少背固定句式 |
| B | Control 与首次配置 | 新用户能完成连接、首张卡片与后续修改；日常操作容易找到 |
| C | 一种有明确用途的新卡片 | 真实复用组件，数据、操作、布局、恢复和双窗同步全部走通 |
| D | 服务器与个人授权验证，再做多用户 | 两个真实账号的数据、连接、请求、额度和退出互不影响 |
| E | 最小内测入口 | 有资格可进入，无资格可留邮箱；邀请状态可管理 |
| F | 手机网页 Control | 同一用户在手机输入，电脑 Display 正确更新，断线可恢复 |

这是建议顺序，不是一揽子开工清单。A/B 可围绕同一条短流程衔接；后面的卡片、账号和手机能力逐项启动。

## A. 自然表达与连续协同

- 把自然表达作为入口，精确规则覆盖稳定高频操作，复杂语义交给已连接模型；模型只输出受限规划和数据，执行与校验由程序负责。
- 优先提高多轮指代：第二项、刚才的资料、这张卡片、把它改成……；利用当前画布和短期上下文，目标不清时只追问必要信息。
- 支持补充和修改已有内容，查询结果可复用仍有效的已有资料；按需创建卡片，控制重复内容。
- 更一致地呈现理解中、查询中、已完成、失败原因、取消与重试；查询失败应明确说查询失败，连接失效应明确提示连接。
- 统一聚焦与打断规则：普通单卡操作帮助定位，明确高亮按原意执行，远期计划安静保存；固定卡片与手动布局受到保护。
- 将用户实际说法加入回归用例，检查误执行、遗漏、数据是否真实及可恢复性。新的本地决策模型评测保持独立，不默认启用实验模型。

验收例子：说“今天要买菜、回邮件、写方案，帮我整理一下”，再说“第二项改成回复客户邮件”，应修改同一张待办；随后查找明确主题的资料，应有来源并能继续引用。

## B. Control 和第一次使用

建议把现有长页面整理成清楚的入口层级，沿用原组件和视觉：

- 日常操作：指令输入、当前画布、实际连接状态、本次执行回执、取消/重试和少量最近操作。
- 内容管理：卡片、提醒、阅读、找卡和画布管理；明确“当前可见”“未来计划”“已到时记录”。
- 设置：模型、语音、输出设备、数据导入导出等按需展开。高级选项在相关场景出现。

首次引导建议是一条短流程：连接 StepFun 或已有 GPT/Pi 授权 → 完成一次真实响应 → 创建首张有用卡片 → 可选开启语音或打开 Display。每一步都有明确完成状态，可跳过可选项，已配置内容不重复询问。

连接恢复单独梳理：区分首次未配置、服务离线、授权失效和可恢复登录；切画布保持配置。GPT 继续复用既有授权，StepFun 的安全保存/重连方式另定，不把 Key 放进浏览器存储来解决便利问题。

提醒与语音配置继续分开，让用户能理解提示音、语音播报、语音输入和系统通知各自做什么。真实设备听感与识别测试在这里补做。

验收目标：新用户不看开发文档也能完成第一次使用；日常用户能迅速输入、查看结果和修正操作，打开设置不会丢失正在处理的内容。

## C. 新卡片与已有卡片增强

建议先评估一种，以下名称表达用途，不预先承诺 Assistant UI 存在同名现成组件：

| 候选 | 实际用途 | 复用与范围 |
| --- | --- | --- |
| 今日安排/日程卡，优先建议 | 按时间查看自己已明确设置的近期安排 | 复用已有提醒计划、时区和 styled 列表/文字；日历服务接入另议 |
| 资料对比/选择卡 | 比较几个方案，保留依据，便于继续提问 | 先复用现有表格、资料卡和真实来源，再评估是否需要独立类型 |
| 网页阅读卡增强 | 读一篇资料，再提炼和整理 | 复用已有受限正文读取、来源与详情阅读，先确认现有卡片的具体缺口 |

开始前核对已安装 registry 的真实组件与用法。新增类型需明确数据来源、允许的操作、默认显示、详情、固定/增长/撤销/恢复/双窗同步和错误状态；模型仍不能生成任意 UI 代码。

后续可把稳定的卡片组合成学习、工作整理、会议准备等场景流程，先围绕实际使用需求验证。

## D. 服务器、个人模型授权与多用户

先区分两个概念：Vivic 登录决定用户能访问哪些画布；模型授权决定使用谁的模型和额度。

第一步只验证部署可行性：用户通过现有 Pi/OAuth 完成自己的登录，在目标服务器方案下能正常请求、刷新授权和断开。明确个人设备与服务器的职责，再确定托管方式；若现有流程受限，再讨论是否需要个人设备连接服务，不重写 OAuth 协议。

验证通过后，多用户至少包含：

- 用户身份、画布、模型连接、正在执行的请求、临时图片和提醒按用户隔离；一人的连接变更或取消不影响另一人。
- 凭据只在受控后端或既有授权存储处理，日志和画布不包含密钥；退出 Vivic 不擅自注销用户的 Pi 或其他应用。
- 为同一用户的多个终端建立经登录授权的网络同步，处理并发、重复命令、断线重连和控制权；提醒交付去重。
- 生产访问入口、会话恢复、服务重启后的数据恢复、备份、必要的请求限制与不含敏感信息的诊断。
- 本机旧画布与服务器画布有清楚的迁移、导入导出和清除边界，迁移由用户明确发起。

当前 BroadcastChannel/本机 owner 与全局后端连接服务不能直接作为这套多用户方案。验收以两个账号同时使用为准：各自的数据和额度独立，A 退出/断开不影响 B。

## E. 内测码与邮箱候补

- 已获资格：使用内测码进入，再完成自己的身份和模型连接。
- 未获资格：留邮箱等待邀请，能理解当前状态；重复提交有清楚反馈。
- 最小管理范围：申请、邀请、已使用和停用状态；申请记录能删除。
- 邀请资格、Vivic 登录和模型授权分别定义，避免一个共享邀请码承担所有身份认证。

邮箱登录方式、邀请码是否绑定邮箱、有效期与邮件发送方式待设计时确认。本次不收集真实邮箱、不发邮件，也不新增支付或复杂运营后台。

## F. 手机网页 Control

先验证一个账号、手机和电脑两台设备：打开自己的画布或配对 Display → 文字输入 → 确认照片/选图后发送 → 按住说话 → 查看结果与必要设置。

- 手机进入自己的已登录会话，明确正在控制哪张画布、哪台 Display。
- 优先验证文字与图片通路，再完善语音权限、取消、重试和后台切换后的恢复。
- 图片预览不自动发送，仅用于当次明确请求；不自动成为图库或后续聊天附件。
- 麦克风、输出音频、相机/选图、浏览器兼容与网络中断均要实机验证。
- Display 保持极简，手机控制按钮和配置留在 Control。

验收以真实手机发出一条指令、电脑正确更新为准；桌面窄屏样式不能代替跨设备验证。

## 当前不扩大的范围

音色复刻继续暂缓；全浏览器关闭后的提醒不作为新增目标。第三种远程 LLM、coding session/tools、扩展或 skills、新 OAuth 协议、长期人格记忆、桌面宿主、音乐、会员支付和卡片商店不自动加入二期。

每轮只推进一条完整流程：明确具体问题 → 给出可评审的交互与范围 → 实现 → 真实输入验证 → 汇总反馈，再做下一轮。建议下一次先定 A/B 的“首次进入—首张卡片—自然修改”流程。
