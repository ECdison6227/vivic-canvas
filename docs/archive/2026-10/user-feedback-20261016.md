本轮由 Agent 直接执行测试，使用用户授权的真实 StepFun Coding Plan 和已有 Vivic/Pi GPT 登录。仅创建独立浏览器里的 TEST 画布，不读取用户现有画布；不再要求用户先重做整套提醒输入。二期仍等待这轮体验收束。

## 已修复的问题

| 反馈 | 原因与修正 |
| --- | --- |
| 换画布后像是没有连上模型 | 模型连接属于后端进程，不属于画布；实测新建画布后仍连接。输入区原来的绿色“决策服务”只代表 API 在线，不能证明模型已连接，现改为实际模型连接状态，并定期刷新。后端重启仍会清空 StepFun 内存 Key，不往文件保存密钥。 |
| C4–C7、D2–D4 连续失败 | 澄清续答范围过宽，周计划、条件提醒、天气等新指令可能继承上一条失败问题。现在识别新指令，同时保留“删除哪个提醒？→五分钟倒计时”这种真正的续答。日期、时区、周期与条件仍由现有确定性适配器计算。 |
| 普通说法被当作不支持 | 普通交流有独立的结构化短回答；自然天气/搜索问法可规划成受限查询，再交给原有真实适配器。没有新增通用工具或代码执行能力。补齐“展示所有卡片”“重新排布居中”“高亮待办第二项”等常见说法。 |
| “帮我找几个开源库”偶发失败 | 最后一次长上下文实测中仍有一次未可靠进入查询；常见找资料/文档/开源库表达现直接进入原检索器，同时保留“找某条提醒”等画布指代和复合要求的澄清。 |
| 简单便笺偶尔创建失败 | 一次真实请求在格式重试后仍未形成可靠动作。明确“记一张便笺：原文”现直接生成校验后的 NoteCard，ID 和时间由程序生成，保留用户原文；自由分析仍走模型。 |
| Orb 到处跳 | 取消根据卡片空位重新选址；工作态固定在屏幕顶部中央，卡片移动、聚焦和新回复不再改变位置。保留原 SmoothUI Orb。 |
| 新提醒放到边上，操作后目标不明确 | 单个可见卡片的新建或修改会聚焦。明确高亮只高亮，批量新增保持整体视图；计划提醒不自动抢镜头。聚焦不改内容密度或固定坐标。 |
| 到点无明确提示、一直停在零秒 | 提示音独立于 TTS；到时有静态暖色边框和背景光、大字事项。一次性提醒与纯计时器在交付后退出 Display，Control 保留记录。普通反馈不能盖掉提醒。 |
| 关字幕后提醒也消失 | store 原来会清空所有字幕状态，背景提醒也依赖这个状态。现保留 reminder 优先级，关闭普通字幕仍能看见到时事项和背景提示。 |

## 提醒显示规则

- 纯计时器只有数字，和带事项提醒分开。
- 一小时以内的普通事项提醒合并呈现。日期/周期/已触发条件有单独的计划容器和标识，不混入普通提醒列表。
- 超过一小时的事项、未触发条件先留在 Control；进入一小时范围时由主控刷新布局，避开固定卡片。第二天/每天任务不在画布上持续占位，也不会因为创建计划自动聚焦。
- 固定卡片保留位置；用户明确聚焦某条远期提醒时可以临时查看，退出聚焦后恢复平常的显示规则。
- 一次性交付后退场；重复提醒推进到下一次，并根据下一次期限决定显示。原始记录、条件关联、撤销与刷新恢复都保留。

提示音默认开启，浏览器需要首次点击/按键解锁音频。可在 Control 的提醒区关闭；它不依赖开启付费 TTS。自动化使用静音浏览器或 Web Audio 替身，没有实际播放扬声器或采集物理麦克风。系统通知仍是独立的默认关闭的静音通知。
