一次发送一项计划提醒，多个动作请分别说明。对时区/日期/条件存在歧义时不会先执行其中一部分。条件是画布内可观察的明确记录；按月/年、节假日、多外部服务条件等没有普遍自然语言支持。

## 语音复刻的具体边界

[官方 Plan 音频接入](https://platform.stepfun.com/docs/zh/step-plan/integrations/audio-api)和[复刻接口](https://platform.stepfun.com/docs/zh/api-reference/audio/create-voice)明确了 Plan 的创建路径，支持先前上传的 5–10 秒 WAV/MP3。已实现这个路径。

[文件上传文档](https://platform.stepfun.com/docs/zh/api-reference/files/create)目前仅明确 `/v1/files`，未列 Plan 上传路径。因此本轮没有猜测 `/step_plan/v1/files`，也没有通过普通 API 自动上传；需要已有文件 ID。没有调用真实用户音频、没有创建真实云音色或实际试听。样本和音色由 StepFun 保存，清除本地数据仅清除本地偏好，不删除云端内容。复刻音色的本地确认列表只在当前后端连接内存中保留，后端重启/换连接后需重新确认。

## 验证记录

Web 单元测试 354 项、API 855 项通过（另 3 项外部条件测试跳过），共 1,209 项；类型和生产构建通过。浏览器使用 5174/8788 独立 context，长期脚本使用 5190 独立生产 snapshot，不同浏览器命令串行运行。

Chromium 全套原始运行 71/73：两个失败是旧断言仍要求离线预录反馈不可用，以及精确聚焦必须经过 LLM；修改测试用语/预期后，相关 AI 和新增流程专项 10/10 通过。它们是分别记录的运行，不拼成一次 73/73。最新 Firefox/WebKit 专项 16/16 通过。

Firefox 的显卡丢失事件可在其他组件渲染期间派发，微任务和定时器仍复现 React 更新告警。最终背景包装不从驱动事件调用 React 状态更新，也不再额外创建探测 context；保留原 Grainient，原生丢失时显示原有静态降级并停止绘制。开发模式专项未再观察到该告警；长期脚本另验真实 context loss 后绘制为零。没有替换 Shader 或批准组件。

默认唤醒词的 3 种合成音色 + 静默会话 4/4 通过：总会话 300,024.7ms，包含初始化；监听态约 298,938.8ms，提交 4,397,056 帧静音 PCM（274.816 秒），没有误唤醒。不是物理麦克风或真实环境噪声验收。最初计时断言未扣除初始化而失败的记录保留在 `evidence/next-plan/default-wake-result.json`；最终记录为 `evidence/next-plan/default-wake-2026-10-15T13-27-21-127Z/report.json`。

新用例在 `apps/web/tests/e2e/next-plan.spec.ts`、`fast-local.spec.ts` 及对应 API/Web 单测；真实只读网页及 Kev 推理证据位于本机 `evidence/next-plan/`。浏览器截图/录屏都是 TEST 画布，音频输出/权限/克隆测试使用静音替身。不得把其结果当作真实账号权限或设备听感。
