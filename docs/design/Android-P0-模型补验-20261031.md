# Vivic Android · P0 模型与语音补验

日期：2026-10-31。用户提供模型配置并授权使用现有服务器 ASR/TTS 后，补验先前缺失的模型链路。

**结果：语音识别、语音合成已通过真实接口与内容核验；引用目标核验发现失败，暂不能启用；启动速度改善但仍未达标。**
P0 八项最新结果为 **6项通过、1项契约差异、1项失败**，不能标成全量通过。

## 模型连接

- 用户提供的 DeepSeek 主密钥通过 `/models` 和真实 JSON 推理测试，返回 `{"ok":true}`。
- 请求模型仍使用用户给出的 `deepseek-v4-flash`，接口返回模型名 `deepseek-flash`。官方说明旧名称仍接受并由当前 Flash 模型服务：[DeepSeek 接口文档](https://api-docs.deepseek.com/)。
- **当前线上 Vivic 任务通道仍是已有的 StepFun 实现**，没有任意 Base URL 或 DeepSeek 提供方配置入口。本轮不部署新提供方适配；任务补验使用用户同次提供的 StepFun Coding Plan，选择 `step-3.7-flash`，仅连接 evaluation 账号。
- 用户提供的语音候选密钥在现有网关返回401。通过已有管理入口建立本次独立验证 Key，只允许 `tts` / `asr`；值仅存本机忽略目录，管理密码没有落盘或输出。
- 语音入口 `https://edsionc.top/api/v1`，现有 Linux 网关转发到已部署的 Mac 模型工作进程。模型为 `qwen3-tts-1.7b` / `qwen3-asr-1.7b`。
- 未修改服务器程序、环境变量、前端产物或部署；正常模型请求、账号内存连接和独立受限 Key 是本轮服务端状态变化。

证据：[model-readiness.json](../android/evidence/P0/model-readiness.json)。所有密钥均未进入源码、报告或 Git；没有保存或使用本次任务不需要的账户凭据。

## 真实语音链路

1. 在指定 evaluation 账号通过正常 `/api/space/models/connect` 连接语音网关，模型列表与权限一致。
2. TTS 合成“请帮我设置五分钟的倒计时。”，得到非静音 WAV，时长4.96秒，合成约6.3秒。
3. 本机转成 AAC/MPEG_4、16kHz、单声道、64kbps 的 m4a，大小45,511字节。
4. 使用 multipart `file`、MIME `audio/mp4` 发到 `/api/space/models/transcribe`，HTTP200，识别原文为“请帮我设置五分钟的倒计时。”。预期短语“五分钟”匹配通过。
5. 独立调用 `/api/space/models/speech` 合成“收到”，HTTP200，返回一个分段，`mime=audio/wav`、`durationSeconds=0.56`、`nonSilent=true`，音频为base64。

这证明一条真实合成语音的 m4a → ASR 内容链路及分段 WAV 返回契约。未使用物理麦克风、未播放音频，不作为真机录音、音色审听或广泛识别准确率结论。

首轮补验的 PowerShell ASCII stdin 管道把中文样本改成了问号，虽然 HTTP200，但内容测试无效。原记录保留于 [api-model-first-attempt.json](../android/evidence/P0/api-model-first-attempt.json)，已明确标注限制；正式结果使用 UTF-8 输入并检查预期短语，没有覆盖首轮观察。

## 卡片引用发现真实缺陷

空 evaluation Space 中用正常命令创建带独立标题的便笺，再发送原计划的 `关于「P0引用便笺」：改成明天`：

- 第一轮要求澄清，约12.7秒。
- 通过 `continuationTaskId` 补充“把这张便笺的正文改为‘明天’”。
- 任务约39.4秒后返回 succeeded，但**原卡没有变化，反而新增了一张便笺**。
- 核验脚本按目标卡内容及卡片总数判为 fail，没有按任务 succeeded 判成功。

因此“引用标题拼接到普通文本”目前不能可靠定位修改目标。按已批准计划 §7.4“命中不了就把这个功能降级到 v1.1”，**引用发送暂不进入可交付能力**；需以后端明确目标ID/引用契约修复并重新核验后才能启用。不是再提供一个模型 Key 就能解决的连接问题。

本轮未改动线上任务执行逻辑。现有勾选、删除、置顶等按 `cardId` 发出的明确 commands 不依赖该标题定位方式。

正式补验明细：[api-model-supplement.json](../android/evidence/P0/api-model-supplement.json)。测试后恢复空 Space、新认领设备已退出，澄清任务已结束；模型连接保留供后续本轮开发使用，仍受现有内存会话寿命限制。

## 启动性能对照

- Wrapper `:app:assembleRelease` 通过，R8、资源压缩和库内置 Profile 已合入。仅以本机 debug 证书签名作对照，包约0.73MiB；不是P4正式签名/覆盖升级验收。
- 同一模拟器实测：原 debug 首屏约45.9秒；优化包首次 cold start 10.849秒；仅对自己包执行 ART speed 编译后 cold start 9.990秒。
- 原生首屏没有网络请求。采样热点分散在 Compose/运行时初始化、类加载和 Binder；采样本身增加耗时，不能拿采样时长作为启动验收数据。
- WHPX可用、实际ABI为x86_64、JIT开启，未发生ARM指令翻译。
- 当时宿主32GiB内存仅余约2GiB；4核模拟器负载均值7.70，其他进程也占用CPU。没有停止用户的浏览器/研究应用，也没有另开模拟器继续增加资源消耗。这些是环境压力的观察，不能据此排除应用初始化开销。
- **仍未达到<1.2秒启动目标，60fps也尚未验收。** 后续需要在资源稳定的隔离设备与真机上复核，并继续优化；不把优化幅度当成达标。

证据：[startup-followup.json](../android/evidence/P0/startup-followup.json)、[采样摘要](../android/evidence/P0/startup-profile-summary.json)、[优化包首屏](../android/evidence/P0/native-smoke-release.png)。
