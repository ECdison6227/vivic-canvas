### 3.1 路由及指卡边界

- 唯一主路由误判：`取消固定喝水提醒`，期望 arrange，实际 edit，概率 0.527，低于拟定直接执行门限。
- `看看最左边那张`：固定画布有两张卡都处于最小 x，程序保守返回歧义；标签却指定其中一张。此例需要人工复核，不能通过强行取第一张来“提高分数”。
- `聚焦一下日程卡`：画布无对应卡，程序返回歧义而非 missing，二者均不应直接操作。
- `高亮第一条`：当前焦点是没有条目列表的纯文字便笺，旧序号捷径不够保守。已在 Git 中收紧并补回归：没有列表字段时不能凭空锚定第一条。**这项修复尚未部署，将随下一次批准的版本一并更新，当前指标仍据原影子版本，不伪称已验证更新后的线上目标准确率。**

因此，99.38% 不是“所有卡片操作都正确”。在这些目标边界修复并验证前，不应开放新的聚焦/高亮直接执行。

### 3.2 原结果差异

唯一差异是联网查询 `上网查查OpenAI这周有什么动态`：基线返回 3 张 SearchResultCard，影子侧旧搜索分支当次返回 error；新路由本身仍正确为 search。

隔时改为顺序重放后，两边均返回相同类型的 3 张搜索卡，差异没有复现。旧搜索模块本身有每分钟 10 次的内存限流，且外部结果和限流窗口没有固定；**不能仅凭这一次实验断言具体原因**。保留差异记录，不宣称所有联网响应都已逐字一致。全部其他输出类型匹配，纯本地路径未发现新行为变化。
