## 8 项接口核验

全部使用 C5 指定 evaluation 账号、空测试 Space 与正常 HTTPS/Cookie 接口；未访问真实用户 Space。
原始脱敏摘要：[api-verification.json](../android/evidence/P0/api-verification.json)。

| 项 | 结果 | 观察 |
|---|---|---|
| a pair → claim → session | 通过 | 200/200/200，同一账号。写请求缺 Origin 返回403；Authorization 返回400 `browser-bearer-disabled`；再次认领返回403 `pair-invalid`。Cookie 为 HttpOnly/Secure/SameSite=Strict，约30天 |
| b tasks「倒计时 5 分钟」 | 通过 | POST202；观测 accepted → running → succeeded，约2173ms；快照真实新增 CountdownCard |
| c 409 时是否已经有任务 | **契约与计划不同** | 过期 expectedVersion 仍返回202，服务端保留任务。相同编号/原文重提返回200；同编号换原文返回409 `request-id-conflict`，GET原任务仍返回200。第二个计时任务最终失败，其成功执行不在本项通过范围内 |
| d card.update 勾选待办 | 通过 | `displayProps.items` 发送完整数组，保留原 item.id，目标项 `done=true`；服务端快照已确认 |
| e transcribe 接受 m4a | **待补验** | 模型状态 configured=false，接口返回503 `model-not-connected`。源码 MIME 白名单含 audio/mp4；本轮只是空文件 MIME 探测，没有真实录音成功证据 |
| f speech 返回格式 | **待补验** | 同样返回503，未取得真实音频。源码契约为 `segments[{audio:base64 WAV,mime,text,durationSeconds,nonSilent}]` |
| g Space 阅读顺序 | 通过核验 | owner.cardOrder 与快照数组顺序一致；桌面视觉位置由 x/y 决定。原计划的“置顶后按更新时间倒序”是手机自己的阅读顺序，不等同于桌面几何顺序 |
| h「关于「标题」：改成明天」 | **待补验** | 任务 failed，提示主模型未连接；目标卡未变化、未新增卡。不能宣称引用已命中，也不能认定已连接模型时不支持 |

## 对后续实现的影响

1. **修正任务重试规则**：不对任意409换新 requestId 重发。先检查错误 code，查询原编号的任务/回执并刷新快照；原任务已存在时继续展示它。过期版本由当前服务端在接受任务后处理。
2. **失败也可能已有部分提交**：任务服务会在多步骤中保留已保存卡片，不能把所有 failed 当成零副作用。P2 的重试交互需核对 createdCardIds、快照和服务端提示，避免整句重复建卡。
3. **建议保留已批准的手机排序**：置顶在前，其余按 updatedAt 倒序；桌面坐标不写回。若负责人希望逐行还原大屏几何顺序，应在 P3 前改为 y/x 排序。
4. **语音与引用补验**：先在 evaluation 账号通过正常入口连接主模型及语音模型，再补真实 m4a、WAV分段返回、同名/多卡引用等用例。当前无可用 evaluation 模型连接，未从真实用户连接中借密钥。
5. **暂不降级产品范围**：引用仍保留在批准设计中，发送能力在核验成功前保持受控；P1 可以先制作视觉系统、连接流程和不发送的输入条。
