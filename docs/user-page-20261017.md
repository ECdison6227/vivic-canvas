# 用户页、三页统一背景与配色设置（2026-10-17）

## 用户要求

1. 把 Control 里的文字、语音这类用户输入放到新的**用户使用页**；页面底部是一个同时支持文字和语音的输入框（参照用户给的图一）。
2. 用户页保持简单：左上角放设置按钮，点击后跳到现在的 Control（设置页）；右上角放一个头像。
3. 展示窗口（副屏）、用户页和设置页使用同一个背景，按用户提供的「VIVIIC 动态背景调色实验室」HTML 实现。默认配色是深色里的「午夜蓝紫」，动画用第二种「流光以太」。用户只能换配色（6 种深色 + 6 种浅色），不能选动画形式。
4. 设置页新增手动更改配色的功能，选完背景随之更换。

## 页面与路由

| 地址 | 页面 | 内容 |
| --- | --- | --- |
| `/` | 用户页 | 设置按钮（左上）、头像（右上）、本次会话的对话记录、底部输入框 |
| `/control` | 设置页 | 原 Control 的全部设置；左上「返回聊天」 |
| `/display` | 展示窗口 | 不变，仍保持极简，背景换成流光以太 |

- 用户页和设置页是**同一个 owner 窗口**的两个视图（`ControlApp`），用 `history.pushState` 切换，浏览器的前进和后退也能用。两个视图都保持挂载，所以切到设置再切回来时，输入草稿、待发送图片、录音和进行中的请求都不会中断；提醒播报和定位刷新同样不受影响。未知路径会跳到 `/`。
- 只读提示（另一个控制窗口正在写入）只显示在当前视图里，仍可在这里「接管控制权」。

## 用户页

- **输入框**（`control/ChatComposer.tsx`，由原 `CommandSection` 改造，逻辑不变）：一条玻璃质感的胶囊，依次是文字输入、`+`（添加图片，也可以粘贴或拖入）、麦克风（按住说话，松开识别）和发送。输入框上方按需出现编号候选、建议、「正在理解…/秒数/取消」、语音状态和图片预览；下方一行小字显示模型连接状态、「识别后自动发送」和「开启单次监听」（本地唤醒，只在语音输入不是“无”时出现）。
- **对话记录**：只保存在本页内存，不持久化，最多 50 轮。每次发送都新开一轮。上一轮的回复固定为它最后的反馈；如果上一轮的请求还没完成就被新指令打断，那一轮会记为「已取消本次请求」。当前一轮的回复就是原来的反馈区（`data-vivic-command-feedback`），正在处理时会实时变化。还没有对话时显示一句欢迎和示例。
- 头像目前是占位图标，没有账号体系，也不读取任何个人信息。
- 深浅外观跟随当前背景：深色用 `#191922` 系的半透明玻璃，浅色用白色玻璃，与 HTML 实验室的界面预览一致。

## 背景（`components/atmosphere/`）

- `pastelAtmosphere.ts` 是 HTML 里 `PastelAtmosphere` 类的 TypeScript 移植，保留了原有的着色器、默认参数（浓度 68、流速 43、光晕 66、明度 70、方向向右）和 Canvas 2D 回退，`mode` 固定为 1（流光以太），叠加层沿用原来的 SVG 颗粒。改动只有两处：
  - 去掉了导出 PNG 用的 `preserveDrawingBuffer`。
  - 噪声 hash 从 `fract(sin(dot(p,…))*43758.5)` 换成不依赖 `sin` 精度的写法。原写法在本机 Intel Arc（ANGLE D3D11）上会在噪声格边界出现可见的矩形接缝：同一时刻定帧对比，相邻像素跳变超过 6 的点有 322 个、最大跳变 22；新写法为 0 个、最大 6，烟雾形态不变。
- `palettes.ts` 收录 HTML 中的 12 套配色：深色为石墨星雾、午夜蓝紫、深海极光、丝绒莓紫、暮色余烬、雨夜森林；浅色为云朵蓝紫、奶油蜜桃、丁香莓粉、薄荷微风、纯白晨光、蓝莓牛奶。
- `AtmosphereBackground.tsx` 在每次挂载时创建并释放自己的 canvas。React StrictMode 下也不会对正在使用的画布调用 `loseContext`。WebGL 丢失时停止绘制，隐藏 canvas，露出底下按配色生成的静态渐变，并标记 `data-vivic-gl-lost`。开启减少动效（系统或设置）时画面静止。
- Display 的 `BackgroundLayer` 改用这一背景，层级不变，仍在 React Flow 变换之外。原 React Bits Grainient 组件文件保留，但已不再挂载。

## 配色设置（设置页「背景配色」）

- `DisplayPreferences` 新增可选的 `darkPalette`（只能取 6 种深色之一）和 `lightPalette`（只能取 6 种浅色之一），沿用原有的 owner 持久化和快照同步。旧记录没有这两个字段时，分别按「午夜蓝紫」和「云朵蓝紫」处理。
- 新装默认主题从「自动」改为「深色」，所以首次打开就是午夜蓝紫。已经保存过主题的用户保持原来的设置。
- 点选某个配色会同时切换到它所属的深色或浅色，三页立即一起更换。主题为「自动」时，如果所选配色正好属于当前时段的外观，就保持「自动」不变；之后白天用所选浅色、夜间用所选深色。设置页底部写明「当前显示」的是哪一套。
- 设置页各区块改成半透明磨砂面板，悬浮在背景上，原有内容和交互不变。

点选编号候选或「取消」时，会作为用户的一条回答单独成行，提问气泡保留在对话里。

## 验证（2026-10-17，Windows / Edge）

自动化全部静音，不开麦克风；使用独立的 TEST context，不碰用户的真实画布。本机 5174 当时被另一个项目（`vivic\source\design\card-atlas`）占用，没有停止它；e2e 改在本工作树自己启动的 5178/8791 上运行，配置文件放在被忽略的 `.cache/` 里。

- 类型检查：contracts、local-api、web 都通过；`vite build` 通过，提示与此前相同（Sherpaw 模块外部化、chunk 体积）。
- Web 单测：415 项全部通过。新增 `BackgroundSettings`（12 套配色、选择后切换深浅、「自动」保持、只读）和配色偏好校验、同步与恢复的用例；背景层用例改为验证流光以太的参数、默认午夜蓝紫、减少动效时暂停以及 WebGL 丢失。第一个提交（只含背景）单独检出后也能通过类型检查和单测（411 项）。
- API 单测：932 通过，2 失败，3 跳过。失败的 2 项是 `wire-json-schema`，原因是本机 CRLF 检出，此前就存在；本轮没有改后端。
- Playwright 全量（Edge）：96 通过，3 失败。
  - `autofit` P1.1：在未改动的基线 `6e7ee11` 上同样失败（同为 -356），是本机既有问题。
  - `canvas-interaction` 拖动、`control` Scenario 1：失败时我正在同一时间运行截图脚本，加重了机器负载；单独各重跑 2 次全部通过。
- 新增 `user-page.spec.ts`，4 项连续 4 轮共 16/16 通过，覆盖：页面布局（设置在左上、头像在右上、输入框在底部）、前进后退切页、每轮回复与草稿在切页后保留、点选候选作为用户回答、配色同时作用于三页并在刷新后保持。点选候选的改动之后，受影响的 control、fast-local、interaction-details、manual-feedback、phase3-settings 也已重跑通过；phase3-settings 的悬停来源用例曾偶发一次失败，重跑 2/2 通过。
- 着色器接缝：原 hash 与新 hash 在同一时刻定帧对比，相邻像素跳变超过 6 的点从 322 个（最大 22）降到 0 个（最大 6）；运行中的页面截图也没有矩形接缝。
