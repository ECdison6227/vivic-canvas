# 规则前置与同次响应首句

本轮依据项目外层的两份执行交接，基于 `dev/decision-layer` / `f6b169a` 在本地隔离分支实现。不沿用 Code Mode，不更换默认 provider 或部署配置。

## 路由

on 模式观察链在调用分类前，尝试配置白名单内的唯一完整卡片契约。规则来源在 trace 的子句记录中标为 `source: rules`，其 `latencyMs` 是本地解析耗时，不能当分类模型推理数据。其他子句仍沿原分类、目标和填槽链；shadow 继续观察真实分类，off 保留原入口。

规则只形成待合并的提案，不先提交部分结果。所有子句仍按顺序构建工作副本、统一校验；任何一项需要澄清则整句无提案。owner 执行、版本/权限检查、删除确认、取消及回执沿用现有机制。没有扩展原先批准的五类直接执行名单。

待办完整列表的解析由原 Todo 契约负责，并供切句复用。普通条目如“写周报”留在同一容器；明确的后续卡片/宿主操作不能被当条目吞入。口语“一个”表示清单容器，明确的“几条/三条”等不等于任意丢项：给出确定数量却不匹配时回退。便笺后口语计时要求也必须保留为第二个子句。

## 多问题候选

保留剩余分类的串行和目标依赖顺序。仓库服务对整个请求加锁，推理进程单并发，底层 `startlux_decide` 不在本地。历史多 questions 对照是同句不同问题，不是多子句路由批次；不能据此证明共享计算或提速。本轮没有配置可用的真实决策服务，未启用未经验证的批量方案。

## 首句

只有经过认证的 SSE 请求（或显式内部测试开关）启用同次响应反馈，普通 JSON 客户端保留原模型请求形状。规划提示要求 JSON 第一字段为独立 `feedback`。宿主只在该字段字符串完整解码后发布一句自然反馈；不透传 say/text、slots、推理或原始 JSON。反馈字段随后从完整对象去除，原契约/校验不变。

StepFun 兼容传输新增可选流读取；GPT 使用已存在的 Responses 流钩子。每次网络重试重置未完成前缀，任务级只发布一次有效反馈；取消/连接变化后不能发布迟到反馈。没有额外的首句模型调用。服务不提供流、字段顺序不符、反馈不安全或不完整时，保留原进度，不能伪造模型首句。

## 首句开关

`VIVIC_STREAM_FEEDBACK` 是这条首句的唯一开关，默认 `on`，即与上文行为完全一致。只有认证 SSE 分支读取它；普通 JSON 客户端、取消/错误以及旧客户端忽略未知字段的路径都不变。`off` 时不向上游请求 `stream:true`、不注入反馈提示、不发送带 `feedback`/`route` 的进度帧，卡片、任务、回执与结果帧照常完成。未设置、`on` 和无法识别的值都按 `on` 处理，避免 env 写错时静默改变线上输出。

回滚不需要改代码：在后端 `env.list` 增加 `VIVIC_STREAM_FEEDBACK=off` 并重建容器即关闭；删除该键（或设为 `on`）并重建即恢复。`apps/local-api/src/config.ts` 的 `streamFeedbackEnabled` 由 `loadConfig` 与在线会话工厂共同使用，两边行为一致。

页面仅复用现有 progress 与瞬时 activity。自然首句不被后续阶段或五秒提示覆盖，最终结果/错误/取消按原生命周期替换；不通过持久化字幕改变画布版本。

## 已验证边界

本轮后端全量 2086 通过、3 原有跳过；105 条 golden 为预期数据的 builder 回放。真实主模型仅 OpenCode Go `deepseek-v4.1-flash`，分类为受控，真实决策批量没有结论。实际主模型在复杂生成中仍会纠错、长尾和字段遗漏，首句改善不代表最终耗时整体下降。完整原始样本、失败与最终复验、浏览器输入入口及可见/回执口径见外层 `outputs/vivic-routing-delivery`，不以历史或受控证据宣称全部外部账号/设备通过。

本轮未部署、推送、合并或修改服务器。密钥不进入仓库、文件或日志。
