# 单卡设计表模板

用途：每张新卡片开工前复制此表，按实际任务填写；用它约定参数、数据、用户操作和视觉。它是设计交接表，**不是 Vivic 已支持的导入包格式**。公共规则见 [卡片开发契约](../CARD_DEVELOPMENT.md)。

## A. 卡片的用途和边界

| 项目 | 需要确定的内容 |
| --- | --- |
| 名称与用途 | 用户解决什么问题；一条具体输入与期望结果 |
| 复用判断 | 能否直接用已有类型；只复用外壳/部件，还是必须新增 cardType |
| 标识 | 拟用 scene_id/cardType；未注册前标为候选 |
| 触发/不触发 | 何时选这张卡；与其他卡片的区别；缺什么需澄清 |
| 数据连接 | 用户输入/已有画布/真实服务；服务文档与版本依据 |

## B. 字段表

每个字段填一行；字段名称是产品内部设计，不把它说成上游接口，除非已核对。

| 字段路径 | 分类 | 类型/限制/单位 | 必填与默认值 | 来源 | 用户可改？控件/话术 | 改动后的行为 | 保存？ |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 按实际字段填写 | 查询配置/展示偏好/服务结果/用户状态/运行态 | 精确到枚举、数量、日期时区、金额币种等 | 未知不自动补成 0/有货 | 用户、具体工具字段、确定计算 | 只读或允许的修改方式 | 仅重排/重新查询/重新计算/其他 | 哪个作用域 |

分别定义：模型可以提出哪些配置修改；用户可以手工改哪些值；服务适配器才能更新哪些事实。UI 和宿主同时执行边界，字段的 `editable: false` 文案不等于已有运行时限制。

## C. 数据与动作例子

- 合法模型输入/输出，以及一份标准化后的卡片数据。
- 最少一份无效数据与预期错误；缺必填、空结果、超长值等按场景选择。
- 每个动作的名称、输入、允许模式/owner、前置条件、是否请求服务、失败/取消结果。
- 查询变化时如何取消旧请求、避免迟到响应覆盖新条件；刷新是否保留备注/收藏。
- 数组项的稳定 ID、失效项与当前选中的项如何处理。

真实响应须脱敏；自行构造的数据标明 DEMO/TEST。参数、服务结果和运行态各举一例，不混放凭据。

## D. 长什么样

| 项目 | 需要确定的内容 |
| --- | --- |
| 默认大小 | 画布 width/height、内容 height，是否固定高度，尺寸变化条件 |
| 内容层级 | 标题、主信息、次信息、标签/来源、操作区 |
| 信息密度 | Display 露出几条、长文本省略/滚动/展开方式；User 详情与编辑区 |
| 复用组件 | 具体参考卡片、SceneCardShell、通用按钮/列表/表格/图表等 |
| 操作反馈 | hover/focus/selected/disabled、加载、空结果、错误、过期、无权限 |
| 动效 | 使用何种现有能力，减少动态效果时怎样呈现 |
| 主题 | 使用哪些宿主 tokens，图表/图片覆盖文字如何保证深浅色可读 |

交付效果图或真实预览，覆盖长标题、多条目、缺图/缺字段；不能只验收一张短文字的理想态截图。

## E. 保存与兼容

- 哪些值跟随卡片实例保存，哪些仅属于当前窗口，哪些属于后端连接。
- 刷新、重新打开、跨窗、导入导出后期望保留哪些状态。
- 数据格式变化时的默认值/迁移，旧字段读写兼容。
- 若为未来扩展包：包缺失、升级失败、禁用与卸载时如何保留实例数据；现阶段未实现的行为标明“待宿主实现”。

## F. 验收与并行交付

- [ ] 字段表、真实 Zod/服务适配、模型提示和 UI 一致。
- [ ] 参数能按约定修改；只读服务事实无法经普通编辑伪造。
- [ ] 空/错/缺字段/取消/过期均有明确处理；旧结果不会覆盖新请求。
- [ ] User 可写 owner / User 只读 / Display 的操作范围正确。
- [ ] 6 深 + 6 浅配色中可读，两个模式与长内容适配；减少动态效果正常。
- [ ] 保存/恢复/导入导出、旧卡兼容及必要测试实际通过。
- [ ] 写清真实服务和模拟数据分别验证了什么。

最后填写负责人、基线、允许修改文件、接口/fixture 的版本以及集成负责人。前端可在协议固定后用 fixture 开发，后端独立适配；共享 Schema/registry 的变更按约定集中接入。
